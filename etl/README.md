# ETL — Team 5 (Dead Ball Data)

Rebuilds the `baseball_dw` warehouse (Lahman + Retrosheet fact constellation) from the source files on an empty MySQL 8 server. There are two equivalent ways to build it:

- **`python run_etl.py`** is the Python runner. It writes a full verification report.
- **`../schema_load.sql`** is one SQL file that does the same build with `LOAD DATA LOCAL INFILE` and no Python at load time. It's generated by `make_schema_load.py` from the real source-file headers.

Both produce byte-identical tables (`CHECKSUM TABLE` matches). `test_schema_load.py` proves this on a fresh MySQL container.

## Requirements

- MySQL 8 (tested on 8.0.46 and 8.4). Quick start with Docker:
  ```
  docker run -d --name dw-mysql -e MYSQL_ROOT_PASSWORD=dwpass -p 3306:3306 -v dw-mysqldata:/var/lib/mysql mysql:8.4
  ```
- Python 3.9+ and `pip install -r requirements.txt`

## Get the source files

```
python get_sources.py
```

- **Lahman 2025:** People, Batting, Teams and Parks CSVs, in `sources/lahman/`.
- **Retrosheet:** 2014, 2018 and 2023 play-by-play, downloaded and unzipped into `sources/retrosheet/`. They aren't stored in the repository.

The script writes `sources/MANIFEST.txt`, with the size and SHA-256 of every input file.

## Build with Python

```
python run_etl.py --password <root password> [--port 3306] --skip-download
```

It ends with **ALL CHECKS PASSED** (exit code 0) or lists the failing checks (exit code 1). Output goes to `etl_output/`:

- `verification_report.txt`
- `table_checksums.txt`

Run it twice; the second run should report *DETERMINISM: table checksums identical*.

## Build with SQL only

```
python make_schema_load.py          # writes ../schema_load.sql
cd <this etl folder>
mysql --local-infile=1 -u root -p -t < ../schema_load.sql
```

Paths inside `schema_load.sql` are relative to this folder. To run it on a clean instance and compare checksums automatically, use `python test_schema_load.py`, which needs Docker.

## Run order

| Step | File | What it does |
|---|---|---|
| 00 | `get_sources.py` | Source files + SHA-256 manifest |
| 01 | `sql/01_ddl.sql` | Database, dimensions, facts, summary table, ETL audit tables (PKs, 17 FKs, indexes) |
| 02 | `sql/02_staging.sql` | Staging tables |
| 03 | `run_etl.py` / `LOAD DATA` in `schema_load.sql` | CSV → staging unaltered (blank → NULL), with `source_file` + `source_row` lineage; rows read per file recorded in `etl_source_audit` |
| 04 | `sql/04_reference_and_unknown.sql` | Eras, Unknown members (key −1), seeded outcome / game-type / matchup dimensions |
| 05 | `sql/05_load_dim_date_season.sql` | `dim_date` (calendar 1871–2025), `dim_season` roll-up, per-league PA rule |
| 06 | `sql/06_load_dim_player.sql` | `dim_player` (SCD Type 1) |
| 07 | `sql/07_load_dim_team_scd2.sql` | `dim_team` (SCD Type 2 on natural key `franchise_id`; gaps-and-islands over franchise-seasons) |
| 08 | `sql/08_load_dim_park.sql` | `dim_park` (Park → City → Region → Country, unique city/region labels) |
| 09 | `sql/09_load_fact_player_season.sql` | Rejects with reason codes, then `fact_player_season` |
| 10 | `sql/10_load_fact_plate_appearance.sql` | Rejects (incl. `NOT_PLATE_APPEARANCE`), then `fact_plate_appearance` |
| 11 | `sql/11_load_agg_pa_season_park.sql` | Summary table at season × park × game type |
| 12 | `sql/12_load_fact_reconciliation.sql` | Lahman vs Retrosheet totals per player × season × measure |
| 13 | `sql/13_verify.sql` | Source → staging → warehouse counts, load reconciliation, totals checks, grain checks, orphan checks, data-quality summary |

Dimensions always load before facts. Every load is ordered by its natural key, so reruns produce identical surrogate keys. Rows that can't be loaded go to `etl_reject` with a reason code, so nothing is dropped silently.
